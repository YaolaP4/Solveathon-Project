1. Executive summary

Federal Funds Matchmaker helps North Carolina state agencies find federal funding that fits their own strategic plans. The challenge sponsor, the NC Office of State Budget and Management (OSBM), wants one central tool for all agencies, especially smaller agencies with limited grant capacity. The build covers two agencies on one standard profile template: NC DHHS, with a profile built from the new NCDHHS Strategic Plan 2026-2030 (published September 2026), and NC DEQ, from the NCDEQ Strategic Plan 2025-2029. Every day at 11:00 UTC (6:00 AM Eastern Standard Time; 7:00 AM during daylight saving time) a Container Apps Job pulls all posted and forecasted Grants.gov opportunities once (about 1,460) and normalizes them once, then scores, reviews and publishes them separately for each agency. Each score runs from 0 to 100; its plan-alignment part is half an Azure OpenAI embedding margin (closer to one of the agency's objectives than to ten unrelated fields) and half TF-IDF word similarity. For each agency's top 45 records, Azure OpenAI also writes a short review whose quotes Python checks word for word.

Staff use a Flask web app on Azure Container Apps. An agency switcher, remembered for the browser session, shows each agency's ranked shortlist, where its coordinator records Pursue / Maybe / Pass. A Statewide page lets a central team such as OSBM see each agency's strong matches, deadlines and decisions, and the opportunities that fit more than one agency. The AI never sets the score, and a person makes every decision. The AI review can move a record to the "not eligible" list only with a verified eligibility quote. A verified quote showing a geographic limit that excludes North Carolina only flags the record and lowers its confidence one step; it never hides it.

The security posture is reasonable for a prototype that holds almost only public data: the app uses HTTPS with HSTS, CSRF tokens, a strict Content-Security-Policy, secure cookies, spreadsheet-safe CSV export and a non-root container, and keys are kept as Container Apps secrets rather than in code or the image. The main gaps are the missing sign-in (T1, High), which lets anyone with the URL read and record decisions for any agency; shared keys and ACR admin credentials instead of managed identity (T5, T6); and, new with the multi-agency build, no per-agency access control (T13). The team plans Entra ID sign-in, Key Vault and managed identity. We recommend adding per-agency roles with sign-in before the OSBM-run pilot (NC DHHS, NC DEQ and one smaller agency) uses real staff accounts.

How the daily job scores an opportunity for each agency (as built)

PartWhat the code doesEvidence
Total score (0-100)45% plan alignment + 25% keyword fit + 15% eligibility (state agency) + 10% time to apply + 5% funder history (USAspending.gov). Computed in Python; the AI cannot change it. The same weights and bands apply to every agency today; neither profile overrides them.src/matcher.py (DEFAULT["weights"], mm_settings, score)
Confidence bandHigh ≥ 55, Medium ≥ 45, Low below 45. The AI review can (a) move a record to "not eligible" with a verified eligibility quote, (b) lower confidence one step when it says the match to the objective is weak, or (c) when it quotes, verified, a geographic limit that excludes North Carolina, lower confidence one step and flag the record "check eligibility". In case (c) the record stays on the shortlist.src/matcher.py (DEFAULT["bands"]), src/rationale.py (check, apply)
Plan alignment (hybrid)0.5 × embedding margin + 0.5 × TF-IDF similarity. The margin is the embedding similarity to each of the agency's objectives minus the best similarity to 10 short off-topic field descriptions. NC DHHS uses the default list (for example defense, arts, physics); NC DEQ's profile has its own (for example health care, law enforcement, early childhood education). The best objective becomes the matched goal.src/matcher.py (similarity, off_topic_anchors); off_topic_anchors in agency/profiles/ncdeq.json
Funder historyAwards under each assistance listing, FY2022-FY2025, looked up for each agency's top 250 candidates and cached for all agencies. An agency counts as a past recipient when awards to names matching its profile pattern reach $100,000; otherwise the share that goes to other state agencies is used.src/matcher.py (aln_record, aln_affinity, affinity_signal); usaspending_recipient_pattern in each profile
Without Azure OpenAITF-IDF similarity alone; AI reviews are skipped and the score breakdown says the meaning-based part is unavailable.src/matcher.py, src/rationale.py, src/aoai.py
How it was tunedOn the 1,037 live opportunities the qualifier had already screened, against whether the qualifier judged them on topic for NC DHHS, using the 2026-2030 profile: AUC 0.90 for the hybrid (76% of its top 50 on topic), against 0.82 for raw embedding similarity (62%) and 0.82 for TF-IDF alone (54%). The full five-signal score reaches AUC 0.92 against "on topic and DHHS can apply". These are AI reference labels used for tuning; precision@10 on fresh human labels is on each agency's Evaluation page. NC DEQ uses the same settings untuned, because there is no DEQ reference set yet. Not re-measured for this report (A16).src/tune_semantic.py, docs/tuning_report.md, docs/finals_field_notes.md

7. Azure Well-Architected quick check

PillarStatusNote
Reliability⚠️The daily job has retries, back-off, a 50-listing safety rule, raw snapshots for replay and a Failed status; if Azure OpenAI is unavailable it still runs, using TF-IDF alone and skipping AI reviews. One pull serves every agency, and agencies are published one after another in the same run: if a later agency fails, the run is marked Failed and that agency keeps its previous list, while an agency already published in that run has its new list. 10. Glossary

C4 model
A way to draw software architecture at four zoom levels: Context, Container, Component, Code.
Container (C4)
A separately running part of a system, such as a web app, a scheduled job or a database. Not the same as a Docker container, although here each one does run in a container.
Container Apps Job
An Azure Container Apps resource that starts a container on a schedule, runs it to completion and records whether it succeeded or failed.
Agency profile
One JSON file per agency on a standard template (mission, goals and objectives with plan page numbers, divisions, keywords, eligible applicant type), built from the agency's strategic plan. Adding an agency means adding a profile.
Statewide view
A page that puts every agency's results side by side for a central team such as OSBM, including opportunities that fit more than one agency.
OSBM
The NC Office of State Budget and Management: the challenge sponsor, which publishes the agency strategic plans.
Data-flow diagram (DFD)
A diagram of how data moves between people, processes and data stores. It is the basis of most threat models.
Trust boundary
A line where the level of trust changes, such as between the internet and the Azure subscription. Threats cluster where data crosses it.
STRIDE
Six threat types: Spoofing, Tampering, Repudiation, Information disclosure, Denial of service, Elevation of privilege.
OWASP Top 10 for LLM Apps
A list of the most important security risks for applications that use large language models, such as prompt injection (LLM01).
Prompt injection
Text placed in a model's input that tries to make the model ignore its instructions.
Hallucination / over-reliance
A model stating something that is not supported by its source, and people trusting model output without checking it. Here the AI never changes the score, and it can move a record to the not-eligible list, or flag a geographic limit, only with a quote that Python finds word for word in the listing.
Managed identity
An identity that Azure manages for a service, so it can reach other Azure services without a stored key or password.
Key Vault
An Azure service that stores secrets and keys and controls who can read them.
secretref
A Container Apps setting that passes a stored secret into the container as an environment variable without writing the value in configuration.
ETag (optimistic concurrency)
A version tag on a stored file. A save only succeeds if the file has not changed since it was read, so two people saving at once cannot overwrite each other.
CSRF token
A random value in each form that proves a submission came from the app's own page, not from another website.
Content-Security-Policy (CSP)
A browser rule that limits which scripts, styles and images a page may load. Here only the app's own files are allowed.
HSTS
HTTP Strict Transport Security: a header that tells the browser to use only HTTPS for the site from then on.
CSV (formula) injection
Text in an exported spreadsheet cell that starts with = and runs as a formula when opened. The export adds a leading apostrophe so it shows as text.
Embedding
A list of numbers that represents the meaning of a text, so similar texts can be compared.
Embedding margin
How much closer a listing is to one of the agency's plan objectives than to the nearest of 10 unrelated fields (such as defense, arts or physics for NC DHHS). It stops long, generic announcements from looking like good matches.
TF-IDF
A word-count method of comparing texts. Here it is half of the plan-alignment signal, and the whole signal when Azure OpenAI is unavailable.
AUC
Area under the ROC curve: the chance that a randomly chosen relevant grant is ranked above a randomly chosen irrelevant one (0.5 = guessing, 1.0 = perfect).
Precision@10
Of the top 10 results, the share that a human labeler marked as relevant.
Zero Trust
A security approach: verify explicitly, use least privilege, assume breach.
Well-Architected Framework
Microsoft's five pillars for reviewing cloud workloads: Reliability, Security, Cost Optimization, Operational Excellence, Performance Efficiency.
NIST CSF 2.0
The U.S. cybersecurity framework with six functions: Govern, Identify, Protect, Detect, Respond, Recover. Tags such as PR.AA name categories within them.
NIST AI RMF
The NIST AI Risk Management Framework, with four functions: Govern, Map, Measure, Manage.
MCSB
Microsoft cloud security benchmark. Control families used here: IM (identity), PA (privileged access), DP (data protection), LT (logging), DS (DevOps security).
